# Phase 2 구현 계획

> 상태: **승인됨 (2026-11-07).**
>
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. 단위마다 `CLAUDE.md`의 담당 에이전트가 구현하고 `verifier`가 검증한다. 체크박스(`- [ ]`)로 진행을 표시한다.

**목표:** `FunctionComponent`, `useState`, `useEffect`, `useMemo`를 구현하고, 이를 쓰는 게임 페이지 `정글 생존기`와 관찰 패널을 만든다.

**설계:** `docs/architecture.md`의 `Phase 2 설계` (구현의 기준 문서). 요구사항은 `docs/requirements.md`.

**구조:** `h`가 자식 컴포넌트를 실행해 태그만 있는 Virtual DOM을 만들고, `FunctionComponent`가 Phase 1의 `renderRoot`, `diff`, `patch`로 화면에 반영한다. 상태는 인스턴스의 `hooks` 배열에 있고, `setState`는 `queueMicrotask`로 `update()`를 한 번만 예약한다.

**도구:** Vanilla JavaScript(ES 모듈), Vite, Vitest, jsdom, Playwright, jsdoc-to-markdown. 새 패키지는 설치하지 않는다.

## 공통 규칙
- 작업 브랜치는 `how-to-song`이다. 답변은 모두 한국어로 작성한다.
- 단위마다 테스트를 먼저 쓰고, 실패를 확인한 뒤 구현하고, `npm test` 통과를 확인한다.
- 화면을 바꾸는 단위는 브라우저에서도 확인한다.
- 단위가 끝나면 핵심 로직과 설계 이유를 짧게 설명한다. 사용자가 직접 설명하고 발표할 수 있어야 한다.
- 단위가 끝나면 `verifier` 검증과 `npm test` 통과 뒤 확인받지 않고 커밋하고 push한다. 이슈를 닫는 키워드는 쓰지 않는다. PR은 매번 먼저 확인받는다.
- 설계와 다르게 구현해야 하면 멈추고 보고한다. 설계를 바꾸면 `docs/architecture.md`에 내용과 이유를 적는다.
- 요구사항과 설계에 없는 기능은 만들지 않고 제안만 한다.
- 내보내는 함수와 클래스에는 JSDoc을 쓴다. `src/` 파일 이름은 `_`로 시작하지 않는다.
- Critical과 Important는 그 단위 안에서 고치고, Minor는 단위 10에서 모아서 고친다.
- `단위 1`, `단위 3`, `단위 4`는 `model: opus`, `effort: high`로 호출한다. 나머지는 에이전트 기본값을 쓴다.

## 검토 중점
테스트가 놓치기 쉬운 입력이다. 각 항목의 테스트는 담당 단위에 넣었다.

1. 0초 직전의 클릭: 시간 초과와 클릭이 겹쳐도 턴은 한 번만 지나간다. (단위 6, 8)
2. 선택을 빠르게 반복: 타이머가 쌓이지 않고 남은 시간이 20으로 돌아간다. (단위 8)
3. 입력기가 한글인 채로 발표 타자: 오류 없이 한/영 안내가 나온다. (단위 8)
4. `localStorage`를 쓸 수 없는 브라우저: 게임은 끝까지 진행되고 기록만 남지 않는다. (단위 8)
5. 엔딩 뒤 `다시 하기`: 타이머가 멈춰 있고, 이름과 최고 기록만 남고, 턴과 스탯이 처음으로 돌아간다. (단위 8)

### 단위 1. setProp과 removeProp
담당: `core-builder`

**파일:** `src/core/createDom.js`, `src/core/patch.js`, `src/core/diff.js`(타입 주석만), `tests/core/createDom.test.js`, `tests/core/patch.test.js`

**만드는 것:** `removeProp(element, name): void`를 `createDom.js`에서 내보낸다. `setProp`을 `속성과 이벤트` 절대로 확장하고, `patch`의 `PROPS`가 `removeProp`을 부르게 한다.

- [ ] 실패하는 테스트 작성
  - `onClick` 함수를 넣으면 클릭에 실행되고, 다시 넣으면 새 함수만 실행되고, 속성에 나타나지 않는다.
  - 문자열 `onclick`은 속성으로 들어간다.
  - `removeProp`으로 핸들러가 지워진다. `PROPS`의 `remove: ['onClick']`을 적용하면 클릭해도 실행되지 않는다.
  - 입력 뒤에 `value`를 `''`로 넣으면 화면 값이 비워진다. `outerHTML`에 `value` 속성이 남는다.
  - 값이 같으면 `value`에 대입하지 않는다.
  - `checked: ''`를 넣으면 체크되고, `removeProp`으로 해제된다.
  - `file` 타입에 `value`를 넣고 지워도 오류가 없다.
  - `<input value="사과">`의 `vdomToHtml` 결과가 바뀌지 않는다.
- [ ] 구현하고 `npm test`, `npm run test:e2e` 통과 확인 (Phase 1 회귀 확인)
- [ ] 검증 뒤 커밋: `feat: setProp에 이벤트와 프로퍼티 처리 추가`

### 단위 2. h
담당: `core-builder`

**파일:** `src/core/h.js`, `tests/core/h.test.js`

**만드는 것:** `h(type, props, ...children): VNode | *`, `normalizeChildren(children): Array<VNode>`. 자식 컴포넌트는 `withoutHooks`로 실행해야 하지만 `hooks.js`가 아직 없으므로, 이 단위는 바로 호출하고 단위 3에서 감싼다.

- [ ] 실패하는 테스트 작성
  - `h('div')`는 `{ type: 'div', props: {}, children: [] }`이다. `props`가 `null`이어도 같다.
  - `h('ul', null, 3, false, [liA, null, ['사과', 0]], undefined, 'b')`의 `children`은 `['3', liA, '사과', '0', 'b']`이다.
  - 빈 문자열은 남고, 나란히 있는 문자열은 합치지 않는다.
  - 자식에 일반 객체나 함수를 넣으면 `TypeError`를 던진다.
  - 속성의 `null`, `undefined`, `false`는 빠지고, `true`는 `''`, 숫자는 문자열이 되고, 함수는 그대로이다.
  - `h(Child, { a: 1 }, '글')`은 `Child({ a: 1, children: ['글'] })`의 결과를 돌려준다. `a`는 숫자 그대로이다.
  - 자식 컴포넌트가 배열이나 `null`을 돌려줘도 부모의 `children`이 정리된다.
- [ ] 구현하고 `npm test` 통과 확인
- [ ] 검증 뒤 커밋: `feat: Virtual DOM을 만드는 h 추가`

### 단위 3. FunctionComponent와 useState
담당: `core-builder`

**파일:** `src/core/FunctionComponent.js`, `src/core/hooks.js`, `src/core/h.js`, `tests/core/FunctionComponent.test.js`, `tests/core/hooks.test.js`

**만드는 것:**
- `class FunctionComponent`: `constructor(component, container, options = {})`, `mount()`, `update()`, `scheduleUpdate()`, 필드 `hooks`, `hookIndex`, `pendingEffects`, `vdom`, `isRendering`, `isScheduled`
- `hooks.js`: `useState(initial)`, `withCurrentComponent(component, run)`(렌더 동안 현재 컴포넌트를 정함), `withoutHooks(run)`(자식 컴포넌트 실행 동안 현재 컴포넌트를 비움). 칸은 `component.vdom === null`일 때만 만든다.
- `h.js`는 자식 컴포넌트를 `withoutHooks`로 실행한다. `hooks.js`는 `h.js`나 `FunctionComponent.js`를 가져오지 않는다.

- [ ] 실패하는 테스트 작성. `setState` 뒤에는 `await Promise.resolve()`로 기다린다.
  - `mount()`가 그리고, `setState` 뒤에 화면이 바뀌고, 바뀌지 않은 DOM 노드는 같은 객체이다.
  - 두 인스턴스의 상태는 분리된다.
  - 맨 위 태그가 바뀌어도 영역은 그대로이고 `this.container`로 다음 `update()`가 동작한다.
  - 컴포넌트가 배열이나 `null`을 돌려줘도 동작한다.
  - 한 핸들러의 `setState` 3번에 컴포넌트는 한 번 실행된다.
  - 함수형 업데이트 두 번은 2가 되고, `setCount(count + 1)` 두 번은 1이 된다.
  - 같은 값이면 렌더하지 않는다. `setState`는 렌더마다 같은 함수이다.
  - `patch`가 실패하면 이전 화면으로 다시 그리고 오류를 던진다. 다음 `setState`가 동작한다.
  - 렌더 중 `setState`, 렌더 밖 Hook, 자식 컴포넌트의 Hook, Hook 개수와 종류의 변경, 두 번째 `mount()`, 마운트 전 `update()`는 오류이다.
- [ ] 구현하고 `npm test` 통과 확인
- [ ] 검증 뒤 커밋: `feat: FunctionComponent와 useState 구현`

### 단위 4. useEffect와 useMemo
담당: `core-builder`

**파일:** `src/core/hooks.js`, `src/core/FunctionComponent.js`, `tests/core/hooks.test.js`

**만드는 것:** `useEffect(effect, deps)`, `useMemo(compute, deps)`, 내부 함수 `depsChanged(oldDeps, newDeps)`. `pendingEffects`의 항목은 `{ hook, effect, deps }`이다.

- [ ] 실패하는 테스트 작성
  - effect 안에서 방금 그린 DOM을 읽을 수 있다. 렌더 중에는 실행되지 않는다.
  - deps 없음, `[]`, `[a]`의 실행 시점이 설계와 같다. 길이가 다르면 실행한다.
  - `Object.is`로 비교한다. `NaN`은 같고, `0`과 `-0`은 다르다.
  - 다시 실행할 때 cleanup이 먼저 돈다. 여러 effect는 cleanup을 모두 실행한 뒤 effect를 실행한다.
  - 함수가 아닌 반환값은 cleanup으로 쓰지 않는다.
  - 변경 목록이 비어 있어도 deps가 바뀌면 실행한다.
  - 렌더나 `patch`가 실패하면 effect는 실행되지 않고, 다음 렌더에서 다시 실행된다.
  - effect 안의 `setState`는 렌더가 겹치지 않는다. 끝없이 예약하면 50번을 넘을 때 오류를 던지고 탭이 멈추지 않는다.
  - `useMemo`는 deps가 같으면 계산하지 않고 저장한 값을 돌려주며, deps가 없으면 매번 계산한다.
- [ ] 구현하고 `npm test` 통과 확인
- [ ] 검증 뒤 커밋: `feat: useEffect와 useMemo 구현`

  - `judgeTyping`은 대소문자를 구분하고, 틀린 글자 뒤도 위치별로 판정하며, 함수 이름보다 긴 입력에서 오류가 없다.
  - `getTitle`의 우선순위

### 단위 8. 게임 화면
담당: `core-builder`

**파일:** `src/phase2/components.js`, `src/phase2/Game.js`, `src/phase2/main.js`, `tests/phase2/Game.test.js`, `tests/e2e/phase2.spec.js`

**만드는 것:** `Game`은 설계의 `Hook의 쓰임` 표대로 Hook을 쓰는 유일한 컴포넌트이다. `components.js`의 `StartScreen`, `PlayScreen`, `StatBar`, `ChoiceButton`, `EventLog`, `PresentationScreen`, `EndingScreen`은 Props만 받는다.
타이머 effect의 deps는 `[game.phase, game.turn, game.event]`이다. 발표 입력창은 함수 이름이 바뀌어도 위치가 같도록 글자 영역과 형제로 둔다.

  - 최고 기록이 다시 열어도 남는다. `다시 하기`는 이름과 기록만 남긴다. 엔딩에서 타이머가 멈춘다. (검토 중점 5)
  - e2e: 난수를 고정해 한 판을 끝까지 진행하고, 시나리오별로 다섯 엔딩을 확인한다.
